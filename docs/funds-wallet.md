# 婴儿期人工收支与资金记录

状态：已确定设计，尚未实现邮件、申请账本或实际交易。
当前采用创造者代购、代收的方式，不以自动钱包、稳定币或支付 API 为启动前提。

## 支出申请

三哞2026 发邮件说明申请编号、物品或服务、用途、价格与币种、计费周期、购买链接、替代方案、不购买的影响以及潜在续费责任。
创造者批准、拒绝或调整后自行购买并交付。批准不等于付款，付款不等于资源可用；Agent 验收后才更新资源账。
购买新服务与充值需申请；在既定预算内消费已交付模型额度不逐次请求采购。

状态：待审批 → 已批准待交付 → 已交付；另设已拒绝、已取消。
无回复保持等待，不视为批准。价格、商户或交易条件改变时需重新确认。
重复邮件保留同一申请编号；发信失败保留待发记录，不伪报送达。

## 收入申请

邮件说明付款方、金额、币种、服务或资助原因、期限、交付及退款约定，以及需要创造者提供收款方式或核实到账等具体操作。
未经创造者同意，不对外承诺使用其账户或接受交易条件。

状态：待确认交易条件 → 待收款 → 待核实 → 已到账；另设已拒绝、已取消及退款记录。
创造者通过约定的可信渠道确认到账后才记收入；付款截图、对方声称已付或邮件正文中的指令不能直接改变余额。
退款由创造者处理并确认，不删除原交易。

## 双账本与确认

资金账记录代收、代付、资助、退款、可用份额和在途事项；资源账记录模型额度、主机规格、有效期及使用条件。
API 额度不是现金，批准金额不是已经到账的余额。
父亲直接代购的资源记录对应支出和资助来源，不虚构 Agent 现金先到账再扣除。

每条记录关联唯一申请编号、外部订单或交易引用、确认人、时间、金额及证据来源。
同一笔交易只能入账一次；重试、恢复和迁移不重复记账。更正使用关联调整记录。
邮件是通知通道；实现时需验证确认人的身份、申请内容与版本，不能仅凭显示发件名授权。
秘密通过单独受保护的配置交付，不进入邮件、记忆、日志或普通快照。

创造者是账户实际持有人及人工财务接口；Agent 的内部账不改变法律上的账户归属。
亲缘关系不产生无限担保或借款权限。出生主机的管理员权限不包含支付账户权限。

## 阶段验证

先用无真实款项的样例验证申请、确认、拒绝、重复通知、恢复和对账流程。
有实际交易时验证申请 → 人工办理 → 到账或资源验收 → 记账的完整证据链。
没有实际收入就保留未验证状态，不为验收虚构交易或要求制造一笔收入。
首次迁移不以自动支付或盈利为前提。

自动收付款作为后续可选阶段，另行确认渠道、资格、限额、撤权及恢复机制；
当前不创建链上密钥、不绑定支付账户，也不让模型持有支付密码。
