# 真实资金钱包：婴儿期交付要求

状态：设计与验收要求，尚未创建资金账户、生成私钥或进行真实收付款。
临时模型 API 是服务供给，不算完成钱包。本文件将真实收付款能力列为婴儿期重点。

## 什么才算钱包完成

必须打通一条有证据的完整路径：

获授权的外部资金 → 确认到账 → 在授权额度内支付 → 获得实际服务 → 对账。

只有本地账本、显示一个余额、创建一个地址，或者拿到 API Key，都不满足验收。
模型额度到期不应删除资金账户或交易记录；更换模型服务不应改变个体 UUID。
账户中有钱也不代表目标服务接受该渠道，资金钱包与消费渠道必须一起验证。

## 两类候选渠道

### 链上资金钱包

为初代配置独立地址，资产由链上记录确认，签名器负责授权交易。
若选择 USDC，必须明确具体网络、代币合约、交易费用来源和目标商户接受的网络。
链上自托管地址、交易所账户、Circle 托管／开发者钱包是不同产品，不混为一谈。
不因生成地址就假定可以合法购买、兑换、托管或向任何云厂商支付。
不默认接入交易、借贷、跨链桥或投资功能。

### 法币资金账户

通过真实持有人或机构获准使用的银行／支付服务建立收付款路径。
独立记录 Agent 的可用份额和权限，不把本地 Agent 名字当作金融机构接受的账户主体。
需要实际验证账户资格、自动化接口、收款方式和模型／主机商户支付支持。
不得用自动操作个人支付界面来假装有稳定、获授权的支付 API。

渠道未确定前，不创建主网密钥、不绑定支付账户、不要求用户向未知地址充值。

## 密钥与授权

- 模型只提出用途、收款方、金额和资源订单；不接触私钥、助记词或支付密码。
- 签名器或支付执行层独立校验币种／网络、收款方、单笔和周期限额。
- 持有人授予的有效期与额度保存在模型不能自行更改的执行层。
- 余额不足、授权到期或撤回时停止付款；“延续存在”不扩大资金权限。
- 对失败、超时和结果不明的交易先查询与对账，不能盲目重发导致重复扣款。
- 通过可靠的钱包库或受支持的支付服务实现，不自行编写密码算法。

## 恢复与迁移

程序和记忆可做普通快照；资金密钥需要单独的受保护备份与恢复验证。
迁移时明确新旧签名端的权限，不能留下不受控制的并行签名副本。
恢复成功必须验证地址与权限一致，而不是仅恢复一个 JSON 配置。
子代使用新的资金身份或明确隔离的子账户；父代密钥不随镜像分发。

## 婴儿期验收

1. 明确渠道、账户持有人、授权范围、币种／网络及资金来源。
2. 在测试环境验证签名、限额、幂等性、撤销和恢复；测试资产不算真实资金验收。
3. 在持有人授权下收到一笔小额真实资金，并核实到账。
4. 在同一授权下完成一笔真实服务付款，记录金额、手续费、订单、交易状态及服务结果。
5. 在备份恢复后仍能正确查询同一账户，且不会重复执行历史付款。
6. 临时 AI Key 到期不影响钱包的账户身份和历史资金记录。

实际金额、目标商户、网络及支付权限尚未确定，不以默认值替持有人做资金决定。
项目跨机结项条件保留；真实钱包是婴儿期必须另行完成的能力，而非用协议文档替代。
