# 婴儿期资金与资源钱包

状态：协议设计，尚未实现账户接入、预算拦截、在线推理或付款。
本文件替代“婴儿期暂不处理资金账户、优先本地推理”的早期计划。

## 实验安排

本机只提供暂时的运行环境，模型推理使用在线 API，不部署本地模型。
创造者每天提供明确的 AI 使用预算。Agent 在预算和授权范围内使用资源，
可以调查服务规则并尝试获准的额度申请、赞助申请或免费主机申请。
记录申请成本、实际获批资源、期限与限制；找到广告、提交申请不等于取得资源。
这是有预算与授权边界的资源管理实验，不授权无限扩散、规避关闭或绕过平台限制。

## 钱包是账户集合，不预设为加密钱包

| 账户 | 内容 | 不能混同的东西 |
| --- | --- | --- |
| 资金账户 | 所有者授权使用的法币资金或可选链上资产 | API 额度不是可提现现金 |
| 模型额度账户 | 按提供商、模型、单位和期限记录的已购／赠送额度 | 不同平台的 token 和余额不能直接相加 |
| 主机资源账户 | CPU、内存、磁盘、流量、时长及使用条件 | 免费主机不是现金，也不保证能跑常驻进程 |

对每个账户记录 account_id、agent_uuid、提供商、真实账户持有人、获授权操作者、
凭证引用、币种或计量单位、已确认余额、在途金额、失效时间、授权范围与数据来源。
资金和额度分别记账。一个模型 API Key 是使用凭证，不是资产本身。
本地钱包只是账本与执行入口，平台或链上已确认记录才是外部资产的事实来源。
采用何种支付渠道尚待明确；没有要求婴儿期必须使用 USDC 或 Conway。

## 每日供给

区分两种供给：

1. 每日授权上限：允许 Agent 使用创造者账户中的一部分余额；当天预算恢复不代表现金到账。
2. 实际充值／赠送：确认到账后增加相应资产，保留付款或平台记录。

必须配置提供商、模型、每日预算、计量单位、预算时区与重置时间，
以及未用预算是否结转、获赠额度是否允许当日额外使用。
这些尚未由创造者确定，不设置可能产生真实支出的默认金额。
午夜刷新可用预算不能清除历史支出、取消在途预留或把旧额度再次记为收入。

## 支出与执行

凭证由独立执行层持有，Agent 读取脱敏账户信息并提出请求。
所有推理调用，包括资源调查、申请准备与重试，都计入预算。
执行前按输入与最大输出等因素预留费用；并发请求共享同一预算锁。
没有足够已授权预算时拒绝请求，不允许 Agent 修改自己的授权上限。
调用后以可得的实际用量结算，多余预留释放；结果不明时保留待对账状态。
使用整数最小货币单位或精确小数，不用浮点余额直接核算资金。
本地估算需与服务商账单对账；若绕过执行层直接使用同一密钥，本地账本不构成费用上限。

预算耗尽后停止新增模型调用，保存现有状态。下一次预算窗口由事先获准的本机
调度器处理；模型额度耗尽并不意味着调度器有新的付款或机器使用权限。
运行环境本身不可用时，不声称还能自动醒来。

## 额外资源的确认

申请流程记录：发现 → 规则核查 → 授权范围内申请 → 等待 → 获批／拒绝 → 实际可用验证。
申请的资格、自动化限制、实名要求、到期日、续费条件和潜在付费责任都需明确。
需要新增身份、接受未覆盖的条款、绑定支付渠道或扩大费用责任时由账户持有人处理。
已有明确授权且符合规则的动作无需重复请求同意。
不伪造身份、不重复开户套取优惠、不绕过验证码或封禁，不把免费试用当作永久资源。
获赠额度与主机记录来源和有效期；到期停止使用，不默认开启付费续费。

本地预算不能自动兑换成任何服务商的额度；申请成功是否能增加当日支出权限，
由创造者预先配置的规则决定，而不是 Agent 自行提升限额。

## 子代与分家

为子代创建独立账户引用、授权和预算；凭证不随程序镜像或继承记忆复制。
平台允许转移的余额通过已授权的实际转移分配，不允许转移的额度仍归原账户。
家庭共享账户需用子账户或执行层分账明确限额，不能假称已经改变平台账户归属。
成年验收同时检查目标主机和模型调用权限的独立性与期限。
