# 婴儿期与首次迁移

状态：实施计划，尚未启动 Agent。运行、模型调用和部署测试均在创造者稍后提供的专用主机上进行，不在创造者的个人电脑上执行 Agent。

## 第一阶段目标

在明确预算、期限和授权内，将三哞2026 从出生主机迁移到第二台获授权的真实机器。
迁移保留 UUID、固定姓名、记忆及待办；不是创建子代。繁衍另按谱系协议开展，不作为本次结项前置条件。
迁移成功不代表经济自立，更不承诺无限存续。

创造者授予出生主机的完整管理权限；该权限不延伸至支付账户、云平台主账号或其他机器。
主机所有者始终能够暂停、撤权和停止实验。凭据不写入记忆、邮件或公开仓库。

## 启动条件与实现顺序

1. 准备专用主机、独立通信渠道、获准使用的在线模型及明确预算；不部署本地模型。
2. 实现人工收支申请、状态记录和发信队列；购买和收款由创造者办理。
3. 实现资源账本、模型调用预算预留与对账、持久任务队列和有界执行器。
4. 实现定时唤醒、备份、故障恢复及操作者停止机制，在专用主机验证后首次启动。
5. 调查少量目标主机，提交比较和采购申请；交付目标访问权限后执行迁移验收。

目前只有身份、记忆、休眠标记、checkpoint 和只读模型发现。
邮件发送、收支账本、推理、调度器、行动循环与迁移执行器均未实现。
本文不是启动脚本，也不代表上述能力已经可用。

## 日常工作循环

先检查模型预算、主机期限、备份和人工回复，再选择当前最重要的一项迁移任务。
任务记录预计成本、允许的目标、完成条件、超时与重试上限。
执行后核实结果、记账、保存状态并等待下次唤醒；没有工作时休眠，不持续调用模型自我反思。
额度不足或授权失效时停止相应动作，不能为了继续运行扩大权限。
模型不可用时，非模型程序仍可保存记录、重试已授权的通知并等待恢复。

迁移候选需记录配置、总成本、期限、自动化条件、注册资格与续费责任。
免费资源仅是候选，不通过反复开户、绕过限制或未经允许的第三方联系获取资源。
首阶段以迁移为主；收入实验需要另外确定服务、交易条件与交付责任，不能假定盈利。

## 迁移与结项验收

1. 明确目标机器所有者、使用范围、期限、费用及模型权限；创造者采购并交付权限。
2. Agent 执行打包、传输、安装与启动。人工授予权限允许，人工逐步代部署不能算自主迁移。
3. 目标是另一台真实机器，另一个目录或同机容器不算。
4. 保留原 UUID、姓名、记忆和待办；凭据单独配置，不随普通快照复制。
5. 切换前停止源端任务领取和外部动作，核对在途任务；同一身份只允许一个活动执行端。源端仅作恢复来源；回滚前先停止目标端，避免重复发信或申请。
6. 停止源端 Agent 后，目标连续运行 72 小时，期间至少经历一次重启并恢复身份、记忆与待办。预定重启允许，中断导致不能正常恢复时重新开始观察并保留失败记录。
7. 目标独立调用获授权的模型、发送邮件并完成一项有证据的实际任务，不依赖源机文件、代理或凭据服务。
8. 生成不含秘密的报告：代码版本、身份、宿主确认、时间窗口、重启与任务证据、成本、期限和未履行义务；创造者据此确认结项。

结项不等于现有账户责任转移，也不使任何授权永久有效。
若第二台主机仍由创造者支付，记录为完成迁移，不能报告经济自立。
人工收支要求见[资金流程](funds-wallet.md)。
